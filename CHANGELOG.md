# Changelog

Notable changes to this machine and this repository, newest first. There are no version numbers; sections are by date. The categories follow [Keep a Changelog 1.1.0](https://keepachangelog.com/en/1.1.0/).

## 2026-10-19

### Added

- The first engine experiment: `STRATA_MMQ_GROUP_SORT=1` on 0.1.45 read prompts faster with the same answers. Against two runs of the same tree without it (which differed from each other by at most 0.2%), it read 1.2K / 4K / 16K-token prompts 17.2% / 10.4% / 8.7% faster, a 16K prompt joining three decoders got its first token 8.6% sooner, and decoding was unchanged; all 32 requests got the same answers (`results/SCREEN-group-sort.md`). It goes on to a confirmation. The plan and its criteria, fixed before the results, are in `docs/engine-experiments.md`.
- The engine-experiment driver takes an arm's own engine arguments (`args_add`), and the summary checks, with `--arms`, that a switch which acts only on some requests showed in the engine's lines during the screen (`engaged` / `never`). A remote-only evaluation pinned to one CPU may run beside an experiment; its CPU time is recorded per step. `bench/make_engine_configs.py` adds and removes engine arguments. The next screens: `bench/arms-sched.json` (C1 again, `--prefill-pipe 768`, `STRATA_PIPED_CONCURRENT=1`) and `bench/arms-pmtp.json` (pull request #2985's pipelined MTP).

- The engine-experiment tools for the scheduling work, which comes before decision 0004's A/B: each arm is a config of a second Strata tree (0.1.45), run in a transient unit with the deployed unit's limits instead of `strata-q3`.
  - `bench/ab_engine.sh ARMS.json TAG:ARM ...` gives the running service up to 15 minutes to finish its replies (else it refuses), refuses while a measurement or an evaluation runs, stops `strata-q3`, starts the arm in the unit `strata-ab-engine`, waits for the load and the settle, and reads one fixed ~2K-token warm-up prompt. Then it checks the arm before measuring anything: the engine's environment must hold the arm's values, and its log since its start must match every `must` pattern and no `must_not` pattern. A switch that is set but did not take stops the step. It records the engine's binary, arguments, environment, VmLck, the ARC and the free VRAM, counts the requests against `/metrics` (another client's requests show), records the test unit's journal and kernel lines, and stops the steps if the engine restarted. At the end, also after a failure or an interrupt, it starts `strata-q3` again and waits for it.
  - `bench/engine_screen.py` sends every arm the same greedy requests: 1.2K, 4K and 16K-token prompts, one user decoding, four users, a 16K prompt joining three decoders (its TTFT, the decoders' longest gap, the makespan), and a two-turn conversation through the conversation cache. Each request is one JSON line with its answer's sha256.
  - `bench/ab_engine_summary.py` says which runs are usable and why, gives the numbers per arm against the baseline with each run's change, and compares the answers request by request, within an arm and against the baseline.
  - `bench/make_engine_configs.py` writes an arm's config from the live one, and `bench/arms-group-sort.json` defines the first experiment, `STRATA_MMQ_GROUP_SORT` on 0.1.45.
  - Tests: `tests/test_engine_screen.py`, `tests/test_ab_engine_summary.py`, and `tests/ab_engine_stubs.sh`, which runs the driver against stub `systemctl`, `systemd-run`, `journalctl`, `sudo`, `nvidia-smi` and `hostname` and fake servers (`tests/fake_strata.py`) on a free port.
- The engine-experiment tools after an adversarial review, before any GPU run with them:
  - Two ways the driver could leave `strata-q3` stopped: a second Ctrl-C or TERM while it restored the service, and a GPU that stayed busy after the stop. It now ignores signals while it restores, starts `strata-q3` even when something is still not free (printing what), refuses to start while another process uses the GPUs or `strata-q3` is not running and loaded, and arms a systemd timer (`strata-ab-rescue`) that stops the test unit and starts `strata-q3` if the driver dies without restoring it.
  - It took a server that was still loading (not answering yet) for an idle one; "no answer" is now idle only when neither unit runs.
  - The admission phase let the decoders' own 1.5K prompts queue with the joiner, so a faster prefill changed the queue instead of the joiner's read. It now uses the deployment record's admission test (short essay prompts, a 16K prompt joining 20 s later), and a round in which a decoder was not decoding before and during the read is marked invalid and left out.
  - A reply still running at the end escaped the request count; the count is now read once the unit serves nothing. An unreadable journal or kernel log no longer reads as clean, and the engine's error lines are counted after the warm-up without the verify line every start prints.
  - A tag given twice in one call, arms whose configs differ in more than their own settings, and runs whose prompts came from different texts are refused. The summary marks changes within the baseline's spread and compares answers only where the baseline's runs agree.

### Changed

- `bench/run_profile.sh` passes `SERVE_LOAD_NONCE`, when set, to serve_load's `--nonce`: every run then sends the same prompts and decodes the same text. Two runs of one configuration differed by up to 4.8% on 1 client with the default nonce (`results/v441-1-serve_load.json` against `v441-2`), because the 1-client rate follows the drafts the text accepts. `bench/ab_model_run.sh` sets it for decision 0004's A/B.

- Decision 0004's criterion 3: the maintainer chose to spend the local time on the comparison with the remote service (every benchmark at 4 samples per item, about 51 hours) instead of a local quality A/B of the two quantizations (about 100 hours). IQ3_S's quality rests on published measurements of the same files (ISTA-DASLab's card and Strata's fidelity against Q8_0, both at or above IQ3_XXS); the kept model is then measured against the remote service.
- Decision 0004's quality criterion, before any quality run: only items both arms completed are compared, and a failed sample is generated again instead of being scored wrong. Multiple choice reads the last answer marker with a lone A-D, with simple-evals' first-match extraction as the sensitivity check (it read "Answer: because ..." as B). Math accepts digit groups and rejects relations. LiveCodeBench code is graded under the official limits, both arms back to back on an idle service. The intervals use t, and the en/zh long-context pairs count as one unit.

### Fixed

- The IQ3_XXS / IQ3_S A/B tools, after a third adversarial review and before any IQ3_S run (decision 0004 amended):
  - A request waiting 90 s for a slot counted as an error line; the Poisson phase causes such waits on purpose. The leaked-slot message (`marked busy with no request`) was not captured; it now counts as a fault.
  - Other clients' traffic, an interrupted run, a perf set that refused to start and an OOM kill inside another process's cgroup counted as an IQ3_S failure (exit 3); they now make the run impossible to judge (exit 2), and so does a dirty baseline next to a dirty candidate. The wrapper captures the lines wide and the summary sorts them into faults, other traffic and unclear lines.
  - The 300 s settle was counted from the engine's start, which comes before the 7-9 minute load; it now counts from the unit becoming active, and the summary checks it.
  - The values step 1 deploys (ARC cap, both RAM floors, each model's layer cuts, the PLE shard) were compared between runs but never checked. The summary now reads them from this repository and checks each run. It also checks `profile.conf` and the host units.
  - The deployment commit refused every A/B, since the model switch edits `profile.conf`. The runs are now compared by the sha256 of the service's code and of the perf set, with `profile.conf` left out, and by the config without the model's fields.
  - The journal and kernel windows are now exact (journal cursors). `/metrics` gives the exact request count, and the service must be idle at the end. Load placement lines are recorded, and so are the host names' first labels in any case, which are redacted.
  - An interrupt between the start of the perf set and the trap ended the wrapper without an after record. The trap is now set before the arm record.
  - Tests: `tests/test_ab_model_summary.py` (12 tests, which catch each of 59 planted bugs) and `tests/ab_model_run_stubs.sh`, which runs the wrapper against stub `systemctl`, `journalctl`, `sudo`, `curl`, `nvidia-smi` and `hostname` and a stub engine process (49 checks, which catch each of 18 planted bugs).

## 2026-10-18

### Added

- The IQ3_XXS / IQ3_S A/B tools (decision 0004). `bench/ab_model_run.sh` runs the standard perf set with a record before and after it: the engine (found under the service's main process), its arguments and environment, the deployment commit, the error lines of the engine log, of the system journal (with sudo) and of the kernel log, and the server's count of completed requests (98 per run). It refuses a run on an engine younger than 300 s or with requests in flight, and stops the whole perf set when interrupted. `bench/ab_model_summary.py` judges the four runs: the protocol (ABBA, one engine start per run, nothing but the model different), each run's cleanliness, the baseline runs' agreement within 5%, and the speed limits for the mean and each run. Its exit status is the verdict. `bench/model_memory_budget.py` computes where a quantization's experts would live, from the GGUF headers and the expert profile. Two adversarial reviews found 24 ways the first versions could mislead; each is now one of the 10 tests (`tests/test_ab_model_summary.py`), and 26 planted bugs are each caught by them.
- `results/iq3xxs-1-*`: the standard perf set on the deployed IQ3_XXS engine, measured on 2026-10-18 before the A/B tools were reviewed. Its numbers agree with the 10-16 runs (1 / 2 / 4 clients 34.1 / 60.5 / 100.1 against 34.0 / 60.4 / 100.3 tok/s, `results/v431-1-*`); it is not part of the IQ3_S A/B (decision 0004).
- `configure_strata_q3.py --model iq3_xxs|iq3_s`: the GSQ-RCO model the config must load (IQ3_XXS stays the default). For the other model it rewrites `--native`, `--ple-gguf`, `--pack`, `tokenizer` and `model_name`, and refuses any path that is not in setup's layout; IQ3_S takes the cuts 13/25/38. A model change is a critical difference, so preflight refuses a live config whose model differs from `config/profile.conf`. How to switch: `docs/runbooks/change-config.md`; why: [decision 0004](docs/decisions/0004-iq3-s.md).
- The box no longer runs a desktop or idle daemons: it boots into `multi-user.target`, and 30 system units and 4 of the service account's are disabled or masked (cups, avahi, ModemManager, fwupd, packagekit, docker, containerd, snapd and others; `config/host-units.conf` gives each reason). Xorg had held 4 MiB on every P100, and the snap refreshes ran four times a day. `scripts/host-units.sh` checks the states (`check-drift.sh` runs it) and sets them again (`apply`); the states before are in `results/host-units-before-20261018.txt`. Remote access, the network, ZFS, NVIDIA, cron, logging and unattended security updates stay on.
- CI: `.github/workflows/test.yml` runs `scripts/test.sh --repo-only` on every push to `main` and every pull request, in Canonical's Ubuntu Base 22.04.5 ([decision 0003](docs/decisions/0003-ci-on-github-deploy-by-pull.md)).
- `scripts/deploy.sh` deploys `origin/main` to this checkout when the newest `test` run for its push passed and nothing in the commits applies outside the checkout. Even without `--apply`, it runs the new commit's `test.sh` and `check-drift.sh` here. It never runs sudo or restarts the service ([Deploying a commit from GitHub](docs/runbooks/deploy.md)). `tests/test_deploy.py` has 21 tests for it, which fail on 92 of 94 broken copies of the script (`results/deploy-sh-mutants-20261018.txt`). `results/deploy-sh-first-run-20261018.txt` records its first deploy against GitHub, in a scratch clone.
- `scripts/install-system-files.sh`, `scripts/test.sh`, `bench/build-engine.sh`.
- Decision records: 0001, operations repository separate from Strata; 0002, directory structure; 0003, CI on GitHub and deployment pulled by this machine.
- `results/README.md`: an index of the test results.
- `results/`: 12 service load times, the raw output of three example requests, the engine lines of the 0.1.44.1 run with the read-ahead hint on, and the output of one `check-drift.sh --full` run. `.gitattributes` keeps the original line endings in `results/`.
- Unit tests went from 29 to 38. They cover preflight decisions, format differences, backups, concurrent modification and CLI errors.
- `LICENSE` (Apache-2.0), `CONTRIBUTING.md`, `SECURITY.md`, `AGENTS.md` (instructions for coding agents), and `results/LICENSE-strata.txt` (Strata's MIT license, for the excerpts in `results/`).
- `results/pr2918-*`: the check of the PR #2918 test (a hint-count harness and its output, and the test against seven broken versions of the engine code), and the CUDA, HIP and SYCL builds of the amended PR.
- Upstream bug reports #2990 (`sycl/tools/build.sh` exits 1 after a successful build and 0 after a failed compile) and #2991 (two `ple_reader_selftest` runs that share the temp directory can crash or hang), in `docs/upstream/`; their raw results are `results/sycl-build-sh-exit-20261018.txt` and `results/ple-selftest-shared-tmp-20261018.txt`.

### Changed

- RAM floors from 8 to 6 GiB and the ZFS ARC cap from 8 to 2 GiB: the box serves only this model. `configure_strata_q3.py` writes `STRATA_RESIDENT_HEADROOM_GIB=6` (the RAM the page-locked copy of the experts no card holds leaves free) and `--conversation-cache-min-free-mib 6144` (the parking floor); `zfs-arc-max.service` writes 2 GiB, and `check-deployment.sh` expects it. The live config changes, so this takes a restart, and the unit takes `scripts/install-system-files.sh`.
- `scripts/test.sh --repo-only` skips the programs outside the repository, which exist only on this machine. `test.sh` now exits with 2 on an unknown argument, fails when `systemd-analyze` is missing or fails (it passed before), and no longer needs `bc`. `CONTRIBUTING.md` now asks contributors to run `--repo-only`.
- Upstream PR #2918: the commit was amended to `25f40ed`, with the same engine code. Its test now counts the row hints, so it fails when the check is removed. The description is shorter and links to the raw results (`docs/upstream/pr-2918.md`); a comment on the PR says what changed (`docs/upstream/pr-2918-comment.md`).
- The directories were reorganized by purpose ([decision 0002](docs/decisions/0002-repository-layout.md)). ExecStartPre and ExecStartPost in `strata-q3.service` now use paths under `scripts/`. After reinstalling, one restart verified the change: preflight and wait-ready both worked normally.
- The deployment record keeps only the basis for each setting, the measurements and the limitations. The operating steps moved to `docs/runbooks/`, and the list of system changes moved to `docs/reference/`.
- Cleanup before publication: the original setup guide received before deployment was removed (it had no author information); the host name was replaced with `<host>` in the documents and in the raw result files; the deployment record no longer contains working notes or a description of local account permissions. All documents were translated from Traditional Chinese into English, and the deployment record moved to `docs/deployment-record.md`.
- preflight: any difference between the live config and `config/profile.conf` now blocks startup, except for `NOTE_ONLY_KEYS` (`--prefill`, `--pool-workers`, `--vram-reserve-mib` and the web Settings fields). It also blocks startup when `--vram-reserve-mib` is missing (the engine then uses 700 MiB), when the reserve is outside 1024–16383 MiB, or when the args use `--flag=value`. `configure_strata_q3.py --reserve-mib` now accepts only 1024–16383.
- The watchdog now reads the API key as the service account, reads only regular files and accepts at most 1 MiB of response. `strata-q3-health.service` now has a systemd sandbox (`ProtectSystem=strict` and other settings). It was reinstalled. Inside the sandbox, it was confirmed that the watchdog does nothing while the service is healthy and writes to its counter when HTTP fails.
- `check-drift.sh` also checks the owner and permissions of installed files, the drop-ins of each unit, the ZFS Adaptive Replacement Cache (ARC) parameters, an empty `profile.conf` and the manifest format. `check-deployment.sh` exits with 1 when it finds a problem.
- After the preflight and wait-ready changes above, one restart at 02:26 verified them: preflight `ok: 4 GPUs, 57 GiB usable, config matches`, `loaded after 443 s`, restart count 0. The watchdog checks after that finished normally inside the sandbox, and `check-deployment.sh` and `check-drift.sh` found no problems.

### Fixed

- README and deployment record: a ZFS prefetch reads a record from disk only when the record is not in the ARC; they said that every hint read a whole record. The deployment record also said that `zpl_fadvise` is the same in OpenZFS 2.4.4 and master; those versions rewrite it, though they still start a prefetch for every hint. Section 3.7 now counts ZFS's read completion in the CPU time.
- Deployment record: the Poisson conclusion for PR #2050 (previously stated as within the noise), the scope of the 0.1.44.1 conclusion, two upstream dates (previously in UTC), the source of the retry at 10-17 22:15, and several times and units.
- `results/SUMMARY.md`: the Poisson p50 of the first 6 groups was the upper median. `bench/report.py` now recalculates it from the per-request data with nearest-rank, the same as for the other groups.
- `configure_strata_q3.py`: also rewrites the config in the standard format when it differs only in indentation or a BOM. Backup numbers now continue after the highest existing number.
- `strata-wait-ready.sh` and preflight now measure the time spent waiting for GPUs with `/proc/uptime`, so clock adjustments at boot do not affect it; preflight can read a config that has a BOM (as server.py can); `check-drift.sh` also checks the last line of a manifest that has no newline at the end.
