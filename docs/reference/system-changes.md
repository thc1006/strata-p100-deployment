# System changes made by the Strata deployment and how to undo them

The table lists everything that this deployment changed outside the repo. `scripts/install-system-files.sh` installs `systemd/` and `scripts/strata-health.sh`; `scripts/check-drift.sh` checks whether the installed versions are the same as the repo.

| Change | Location | How to undo |
|---|---|---|
| CUDA 12.9.1 toolkit (toolkit only; the driver was not changed) | `~/cuda-12.9` (the engine depends on it; *do not delete it*) | Delete the directory (the engine will no longer run) |
| Desktop files of the CUDA toolkit | `~/.local/share/applications/nsight-compute.desktop`, `nsight.desktop`, `nsight-systems.desktop` and `nvvp.desktop`, which the CUDA installer wrote on 2026-10-16 05:29–05:30; they start Nsight and the Visual Profiler from `~/cuda-12.9` (`results/host-state-20261030.txt`) | Delete the four files |
| The rebuild rehearsal's sandbox | `~/rebuild-rehearsal`: the sandbox of 2026-10-30, with the rehearsal's toolkit, clones, engine build and logs (10,868,772,211 bytes by apparent size on 2026-10-30 at 10:01, `results/rebuild-rehearsal-copies-20261030.txt`); the service does not use it. Its guard ran in the user scope `rrg-guard.scope`, which was inactive at that time (same file) | `rm -rf ~/rebuild-rehearsal` |
| CUDA installer | `~/downloads/cuda/cuda_12.9.1_575.57.08_linux.run` (5.5 GiB, `results/rebuild-sizes-20261022.txt`; can be deleted; *do not install the 575 driver in it*) | `rm` |
| apt packages | `python3-venv`, `python3-pip`: setup.sh installed them with `sudo apt-get install -y python3 python3-venv python3-pip`, which also brought in 16 dependency packages (for example `python3-dev`; `results/apt-history-20261016.txt`). `gh`: installed separately on 2026-10-16 to work with GitHub; the service does not need it | `sudo apt remove python3-venv python3-pip gh`, then `sudo apt autoremove` |
| Strata source code and venv | `~/dev/strata`: a worktree of `~/dev/strata-git` at the commit `config/deployed-artifacts.sha256` pins (until 2026-10-19, 0.1.43.1 from a zip) | Delete the directory |
| Config backups | `~/dev/strata/strata-iq3_xxs.json.before-p100-q3*` (the backups that `tools/configure_strata_q3.py` makes before each write), and those of 0.1.43.1's config in `~/dev/strata-0.1.43.1` | Delete the files after you confirm that you do not need to roll back |
| Old copy of the tool | `~/dev/strata-0.1.43.1/configure_strata_q3.py` (the version from 2026-10-16, moved with the 0.1.43.1 tree on 2026-10-19; neither the service nor the scripts use it; the current version is in `tools/`) | Can be deleted |
| Model data | `~/dev/Strata-data` (217.9 GiB on disk on 2026-10-21: models 121.8, packs 89.7, mtp 6.5 GiB; `results/strata-data-du-20261021.txt`) | Delete the directory |
| Strata trees for version testing | `~/dev/strata-git` (a partial clone of upstream; `~/dev/strata`, `~/dev/strata-0.1.44.1`, `~/dev/strata-0.1.45` and `~/dev/strata-0.1.45-locked` are its worktrees), `~/dev/strata-0.1.45-locked` (the branch of upstream PR #2918 at `25f40ed`, as it was before its rebase on 2026-10-20, with its CUDA, HIP and SYCL build directories `build-cuda12`, `build-hip` and `build-sycl`), `~/dev/strata-pr2050` (PR #2050, not adopted), `~/dev/strata-pr2985` (PR #2985, `bench/arms-pmtp.json`; a copy of `~/dev/strata-0.1.45` whose `.git` file still names that worktree's entry, so git shows the same branch in both), `~/dev/strata-0.1.43.1` (0.1.43.1 from a zip, which the service ran until 2026-10-19, kept for a rollback) | Remove a worktree with `git -C ~/dev/strata-git worktree remove <dir>`, and delete the other directories. Keep `~/dev/strata-git` while `~/dev/strata` is its worktree: without it the service's tree has no git data, `scripts/check-drift.sh` reports drift and `scripts/deploy.sh` refuses every commit, and the rollback in [Evaluating and upgrading Strata](../runbooks/upgrade-strata.md) needs it. Keep `~/dev/strata-0.1.43.1` while a rollback to 0.1.43.1 may be wanted |
| systemd units | `/etc/systemd/system/strata-q3.service`, `strata-q3-health.{service,timer}`, `zfs-arc-max.service` | `sudo systemctl disable --now <unit>`, then delete the files and run `sudo systemctl daemon-reload` |
| Memory limit of the maintainer's account | `/etc/systemd/system/user-1003.slice.d/50-memory.conf` (`MemoryMax=6G`, `MemorySwapMax=0`: [decision 0007](../decisions/0007-memory-limit-of-the-maintainers-account.md), a copy of `systemd/user-1003.slice.d/50-memory.conf`); from 2026-10-21 09:22 until it was installed, the same settings by `systemctl set-property --runtime`, in `/run/systemd/system.control/user-1003.slice.d/` until a reboot | Delete the directory and run `sudo systemctl daemon-reload`: from the next boot on, the account has no limit. Until then the copies that `set-property --runtime` wrote keep it; to lift it at once too: `sudo systemctl set-property --runtime user-1003.slice MemoryMax=infinity MemorySwapMax=infinity` |
| Watchdog script | `/usr/local/sbin/strata-q3-health` (a root-owned copy of `scripts/strata-health.sh`); its counters are in `/run/strata-q3-health` (tmpfs, cleared at reboot) | Delete the file |
| Log rotation | `/etc/logrotate.d/strata-q3` (rotates when the log is larger than 50 MiB, keeps 8 copies) | Delete the file |
| ZFS Adaptive Replacement Cache (ARC) | `zfs_arc_max=2 GiB` (8 GiB before decision 0004), `zfs_arc_shrinker_limit=0` (runtime settings, applied by `zfs-arc-max.service`) | `sudo systemctl disable zfs-arc-max`, then reboot |
| Host units | the boot target is `multi-user.target`, and the units `config/host-units.conf` lists are disabled or masked; `scripts/host-units.sh apply` sets them | `sudo systemctl set-default graphical.target`, then enable or unmask the units as `results/host-units-before-20261018.txt` records them (a user unit with `systemctl --user`) |
| setup settings | `~/.config/strata/settings.json` (records the data directory) | Delete the file |
